# Kalika E-Commerce Platform — Technical Documentation

## 1. Overview

This is a **B2B e-commerce punchout catalog** that integrates with **SAP Ariba** procurement networks. It lets buyers in Ariba browse a supplier's catalog from within their procurement system and return the selected items as a shopping cart (cXML PunchOut order).

The project has two backends:
- **Django** — public-facing catalog, cart, punchout cXML handling, chatbot
- **FastAPI** — internal admin panel for managing products, users, and orders

---

## 2. What Is PunchOut?

PunchOut is a **cXML (Commerce eXtensible Markup Language)** protocol that lets a buyer in an Ariba procurement system "punch out" to a supplier's external catalog, shop, and return the cart seamlessly to Ariba.

**The flow:**

```
[SAP Ariba Buyer]
      |
      |  1. Buyer clicks "PunchOut" in Ariba
      |     POST /punchout/setup/  (cXML PunchOutSetupRequest)
      v
[Kalika Django App]
      |
      |  2. Returns cXML PunchOutSetupResponse
      |     with <StartPage URL> containing session
      |
      |  3. Buyer's browser opens Kalika catalog
      |     (session-based, no login required)
      |
      |  4. Buyer shops, adds items to cart
      |
      |  5. Buyer clicks "Checkout" / "Return to Ariba"
      |     POST to Ariba's return URL  (cXML PunchOutOrderMessage)
      v
[SAP Ariba]
      |
      |  6. Ariba creates a requisition from the returned cart
      |     Buyer completes procurement workflow in Ariba
```

## 3. Credentials / Identifiers from SAP Ariba

When you register as a supplier with SAP Ariba, you receive:

| Credential | Example | Where Used |
|-----------|---------|------------|
| **ANID** (Ariba Network ID) | `AN01284122159-T` | `<From><Credential domain="NetworkID"><Identity>` |
| **Supplier DUNS** | `651009354` | `<To><Credential domain="DUNS"><Identity>` |
| **SharedSecret** | (supplier-defined) | `<Sender><SharedSecret>` — authenticates the cXML sender |
| **BuyerCookie** | (per-session) | Generated by Kalika, identifies the buyer session |
| **PunchOut Return URL** | (Ariba-provided) | `<BrowserFormPost><URL>` — where Kalika POSTs the cart back |
| **From Identity** | (buyer's org ID) | `<From><Identity>` — identifies which buyer organization |
| **Buyer Identifier** | (per-user/buyer) | Mapped to a local Django `CustomUser` account |

**In `.env`:**

```env
PUNCHOUT_ANID=AN01284122159-T           # Ariba Network ID of the supplier
PUNCHOUT_SUPPLIER_DUNS=651009354        # Supplier's DUNS number
PUNCHOUT_SHARED_SECRET=<your-secret>    # Password shared between Ariba and supplier
```

## 5. Complete Process Flow

### 5.1 PunchOut Setup (Ariba → Kalika)

1. Buyer in SAP Ariba clicks "PunchOut" for Kalika's catalog
2. Ariba sends an HTTP POST to `/punchout/setup/` with `Content-Type: application/x-www-form-urlencoded` containing a `cxml-urlencoded` field (URL-encoded cXML)
3. The `punchout_setup` view receives the request
4. It URL-decodes the cXML payload and parses it with `lxml.etree`
5. **Authentication:** Extracts `<Sender><Credential><SharedSecret>` and verifies it matches `PUNCHOUT_SHARED_SECRET`
6. **Extracts identifiers:**
   - `<From><Credential domain="NetworkID"><Identity>` — buyer's Network ID
   - `<BuyerCookie>` — if present, or generates a new one
   - `<BrowserFormPost><URL>` — the return URL where cart is POSTed back
7. **User handling:** Looks up or creates a `CustomUser` with `buyer_identifier` matching the From Identity
8. **Session setup:** Stores in the Django session:
   - `is_punchout = True`
   - `punchout_return_url` (from `<BrowserFormPost><URL>`)
   - `punchout_buyer_cookie`
   - `punchout_from_identity`
9. **Edit/Inspect mode:** If the cXML contains `<ItemOut>` elements, the system:
   - Looks up matching products by `SupplierPartID`
   - Adds them as `CartItem` entries in the session cart
   - Immediately redirects to `return_cart_to_ariba` (this happens when Ariba sends an existing requisition back for editing)
10. **Setup mode (default):** Returns a `PunchOutSetupResponse` cXML:
    ```xml
    <cXML ...>
      <Response>
        <Status code="200" text="OK"/>
        <PunchOutSetupResponse>
          <StartPage>
            <URL>https://kalikaindia.com/?punchout_session=<session_key></URL>
          </StartPage>
        </PunchOutSetupResponse>
      </Response>
    </cXML>
    ```
11. Ariba opens the buyer's browser to this URL, landing on the Kalika catalog with the session active

### 5.2 Shopping (Inside Kalika Catalog)

1. Buyer browses products at `/` (home), `/products/`, or `/category/<main>/<sub>/`
2. Product images are served via **S3 presigned URLs** (1-hour expiry, cached in LocMemCache)
3. Buyer searches via `/search/?q=<term>`
4. Buyer adds products to cart via `cart/add/<item_id>/` (AJAX + redirect fallback)
5. Cart is keyed by **Django session** (no user account needed publicly)
6. Cart quantities can be updated via AJAX at `cart/update_quantity/`
7. Header shows cart item count (from `cart_item_count` context processor)
8. Buyer can also use the **Gemini chatbot** at `/chatbot/chat/` to ask product questions

### 5.3 Return Cart to Ariba (Kalika → Ariba)

1. Buyer clicks "Checkout" at `/cart/checkout/`
2. If session has `is_punchout=True`, the `checkout` view calls `_prepare_and_return_cart_to_ariba`
3. This function:
   - Fetches all `CartItem` for the session
   - Builds a `PunchOutOrderMessage` cXML containing:
     - `<BuyerCookie>` — identifies the buyer session in Ariba
     - `<PunchOutOrderMessageHeader operationAllowed="create">` with `<Total><Money>`
     - One `<ItemIn>` per cart item with: `SupplierPartID`, `UnitPrice`, `Description`, `UnitOfMeasure`, `UNSPSC`
   - Signs with `SharedSecret` and identifies sender via `PUNCHOUT_ANID` / `PUNCHOUT_SUPPLIER_DUNS`
   - Creates `PunchOutOrder` and `PunchOutOrderItem` database records (audit trail)
   - Deletes all cart items and flushes the session
   - Renders `return_to_ariba.html` — a page with a hidden form that auto-submits the cXML via POST to the `punchout_return_url`
4. Ariba receives the cart and converts it into a **requisition** in the buyer's procurement workflow
5. Buyer completes the approval and ordering process inside Ariba

### 5.4 Admin Panel (FastAPI)

Accessible at `/fastapi-admin/`:

1. **Login** — separate auth from Django (uses session-based auth checking `accounts_customuser` table)
2. **Dashboard** — stats: total sales, products, users, pending orders, category breakdown (Chart.js)
3. **Items** — full product listing with DataTables (server-side processing, search, sort, pagination)
4. **Add Product** — form with S3 image upload
5. **Edit Product** — load by item_id or item_code, update fields and images
6. **Bulk Modify** — CSV upload for bulk add / update price / update description / delete
7. **Bulk Modify Properties** — CSV upload to update item properties by item_code
8. **Export** — background CSV export of products
9. **Categories** — management page (main / sub / sub-sub categories)
10. **Orders** — view pending and completed orders
11. **Users** — CRUD for admin users
12. **PunchOut** — view punchout response history
13. **Analytics** — category analytics with charts
14. **Settings** — application settings page

## 6. cXML Message Formats

### 6.1 PunchOutSetupRequest (from Ariba)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE cXML SYSTEM "http://xml.cxml.org/schemas/cXML/1.2.014/cXML.dtd">
<cXML payloadID="1680000000-12345678@ariba.com" timestamp="2026-01-01T12:00:00-05:00" version="1.2.014">
  <Header>
    <From>
      <Credential domain="NetworkID">
        <Identity>AN01284122159-T</Identity>
      </Credential>
    </From>
    <To>
      <Credential domain="NetworkID">
        <Identity>buyer-org-network-id</Identity>
      </Credential>
    </To>
    <Sender>
      <Credential domain="NetworkID">
        <Identity>buyer-org-network-id</Identity>
        <SharedSecret>secret123</SharedSecret>
      </Credential>
      <UserAgent>Ariba</UserAgent>
    </Sender>
  </Header>
  <Request>
    <PunchOutSetupRequest operation="create">
      <BuyerCookie>abc123</BuyerCookie>
      <Extrinsic name="UserEmail">buyer@company.com</Extrinsic>
      <BrowserFormPost>
        <URL>https://buyer.ariba.com/punchback</URL>
      </BrowserFormPost>
      <SelectedItem>
        <ItemID>
          <SupplierPartID>KAL-001</SupplierPartID>
        </ItemID>
      </SelectedItem>
    </PunchOutSetupRequest>
  </Request>
</cXML>
```

## 10. Setting Up PunchOut with SAP Ariba (Supplier Onboarding)

To connect this catalog to SAP Ariba as a supplier:

1. **Register as an Ariba Discovery supplier** or work with your buyer to add you as a supplier
2. **Provide these to Ariba / your buyer:**
   - PunchOut setup URL: `https://yourdomain.com/punchout/setup/`
   - PunchOut return URL: `https://yourdomain.com/punchout/return-cart/`
   - Supplier DUNS: `651009354`
   - ANID: `AN01284122159-T`
   - SharedSecret: (you define this, must match between both sides)
3. **Create a CIF file** (Catalog Interchange Format) — sample at `kalika_punchout.cif`
   - Each item must have: ItemCode, Description, Price, UoM, UNSPSC
   - Mark items with `PunchOut Enabled=TRUE`
   - Set PunchOut URL to your setup endpoint
4. **Upload the CIF** to Ariba via Ariba Catalog Upload
5. **Test:**
   - A buyer in Ariba searches for your catalog
   - Clicks your catalog → browser opens to your site
   - Adds items and clicks "Return to Ariba"
   - Cart appears as a requisition in Ariba

## 11. Security Notes

- **Rate limiting:** 20 requests/minute on `/punchout/`, `/admin/`, `/accounts/login/`
- **IP blocking:** 22 known malicious IPs blocked in middleware
- **Path protection:** `.env`, `.git`, `phpinfo`, path traversal blocked
- **Session:** DB-backed sessions, 24hr expiry, HTTPOnly, SameSite=Lax
- **Image URLs:** S3 presigned URLs with 1-hour expiry
